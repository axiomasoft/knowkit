# PostgreSQL Lifecycle Store (`PdoLifecycleStore`)

Implements `KnowKit\Port\LifecycleCommandStore` over the existing PostgreSQL metadata migrations. `LifecycleCommands` prepares host authorization before BEGIN, then locks the tenant, every membership KB in sorted order, the source, affected generations and jobs. Transactions use READ COMMITTED, a 500ms lock timeout, a 2s statement timeout and a 2s wall deadline checked before commit. Lock timeout remains typed unavailable. Composition injects the existing `DomainEventFactory::create` callback, preserving the Adapter → Port/Domain package boundary.

Ordinary acceptance preserves usable historic versions. Publication checks sealed exact memberships and synchronous ancestor usability before CAS of the default snapshot. Correction requires a ready same-source replacement and can activate a compatible sealed snapshot in the same commit. It preserves all unaffected content members. Urgent correction immediately blocks the exact erroneous version even when no replacement exists. Historical Usage, citation source/version/IR/spans and hashes remain unchanged; invalidations are separate records.

Identity revoke and delete persist authoritative future-version tombstones, including before source registration. Consent/access revoke additionally advances the source policy epoch. ACL-only invalidation of prepared owner receipts uses the existing `PdoPolicyEpoch`; it does not imply withdrawal of every actor's consent. Commands, epochs, markers, idempotency receipts and P2.1 outbox append commit or roll back together. Event creation reuses `DomainEventFactory`. Same-key replay creates no new epoch or event; a changed fingerprint or event payload digest is a conflict. Delivery, transport leases and inbox are P3.5 work.

Legal hold is a retention flag independent of read permission. It protects owned resources, persists on revoked/deletion-requested sources and never permits disclosure. Removing a hold restores no read permission. A hold placed after deletion starts fails with `HOLD_TOO_LATE`. Delete requests freeze owned inventories using the existing relational inventory trigger; unknown resources remain unknown and external-owned bytes are excluded. An empty owned inventory remains an internal pending intent, not a public DeletionTask or erasure receipt. No command performs physical/provider deletion or declares purge complete; recovery archival and backup obligations require their owning workflows.

The guarantee is local PostgreSQL serialization. An external owner receipt is acquired before the transaction and checked against current local epochs and receipt expiry under the guards. `LifecycleGuarantee` records the host's explicit 1..5 second freshness contract separately; a missing or expired freshness bound is unknown. The external owner's check-to-commit window follows that owner's contract. Delayed owner responses cannot bypass a locally committed revoke, and no instantaneous distributed atomicity is claimed. In-transaction acceptance/staging callbacks must perform only SQL over preloaded, verified metadata; provider, blob and process I/O belong outside the transaction.
