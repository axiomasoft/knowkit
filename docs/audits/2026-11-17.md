# Repository audit — 2026-11-17

The owner's existing changes were preserved in snapshot commit `b06785c` before
the audit. Four parallel reviewers investigated Core, PostgreSQL/pgvector,
worker/deployment, and optional integrations; the coordinator audited QA, CI,
dependencies and the combined result. Database changes received a second review.

This is a repository-wide engineering audit with reproduced defects and local
verification, not a claim that every execution path is proven safe. Existing
package boundaries, offline execution, exact model qualifications and pinned
third-party records remain intact. Nothing was pushed, published or released.

## Correctness and security fixes

| Area | Reproduced problem | Change and regression coverage |
| --- | --- | --- |
| PostgreSQL guards | Temporary tables could hide tombstones or replace sealed-generation state | Core migration 014 and vector migration 003 pin function search paths to `pg_catalog, owning_schema, pg_temp`; direct SQL adversarial tests |
| Migration ledger | A temporary `schema_migrations` could cause replay of existing DDL | Explicit `pg_temp` ordering; upgrade, history, checksum and caller-search-path preservation tests |
| Transactions | A lost connection during BEGIN escaped as a raw PDO exception | Return the typed unavailable outcome without executing the operation or exposing SQL details |
| Semantic profiles | Secret/path keys escaped validation inside nested arrays | Bounded recursive traversal of JSON objects, lists and associative arrays |
| Disclosure budgets | Negative tokenizer results bypassed the token budget; addition could overflow | Reject negative results and compare against remaining capacity before addition |
| Model egress | A capability could expire inside the host preparation callback, then still dispatch | Recheck immediately before dispatch; expired capability produces KnownNotSent |
| HTTP transport | Invalid method/request-target bytes reached the stream wrapper | Reject malformed request lines and overlong targets before network access |
| Worker packaging | Transitive dependency extras were omitted (50 installed distributions) | One extras-aware dependency resolver shared by production builders |
| Runtime inventory | Symlinks, hardlinks and special files were accepted by BOM traversal | Reject unsafe entries and linked manifests; reject unsafe staged roots |
| Native libraries | Wheel libraries were duplicated under build-machine paths; missing external libraries could pass | Reuse included wheel libraries, reject unresolved external libraries, remove duplicate PDF builder traversal |
| QA reports | Root JUnit summary failures/count mismatches were ignored; child diagnostics were discarded | Validate both summary levels; retain bounded stdout/stderr tails |
| Test autoload | Later optional Composer loaders could silently select stale copied Core | Re-register candidate source priority only for connected packages; fresh-process tests cover both orders and optimized classmaps |
| Worker acceptance | A hand-built old profile signature tested mismatch instead of unavailable qualification | Bind the test to the pinned exact signature and separately assert mismatch and unavailable outcomes |
| Capacity diagnostics | Missing leaf `cpu.max` aborted otherwise valid load measurements | Resolve the visible cgroup mount and inherited limits; report missing/invalid metadata honestly without claiming hardware qualification |
| Load-test IPC | The 100,000-chunk search configuration exceeded an implicit 1 MiB line limit; child responses/stderr were unbounded | Explicit 16 MiB config and 1 MiB response frames, complete-frame checks, short-write handling and bounded nonblocking diagnostics with process cleanup |
| Sandbox compatibility | Denying `clone3` with EPERM prevented glibc's safe legacy pthread fallback in freshly built runtimes | Keep `clone3` denied with ENOSYS, preserve the filtered legacy clone path and socket denial; native thread/seccomp regression |
| Runtime freshness | Reused PDF/OCR test runtimes and capacity reports were not bound to current builder inputs | Record three builder hashes plus the worker lock digest, reject stale test runtimes and invalidate old measurements; no source-checkout dependency added to production runtime validation |

Core and vector migrations are additive. Previously deployed migration files and
checksums have not been rewritten. Apply the normal explicit migration entry
points before relying on the hardened SQL guards in an existing installation.

## Structure, performance and test infrastructure

- Core still has no third-party runtime Composer dependency. The seven-package
  DAG, optional project lockfiles and PHP floors pass their existing guards.
- CI now selects 29 portable Core/architecture groups and 14 optional groups,
  replacing the two-group bootstrap-only workflow. Original bootstrap and full
  qualification profiles remain available with explicit unselected groups.
- Optional Answer/pgvector/HTTP/Laravel sources receive Level 8 analysis using
  their own installations. Chatom's pinned sibling host and AgenTools installed
  qualification are deliberately separate prerequisites.
- CI collects Core coverage and uploads reports, including failed QA reports.
  Obsolete workflow runs are cancelled. Python protocol regressions run offline
  after a frozen installation and are now discoverable through the QA registry.
- `CanonicalUnits` constructs and validates a canonical map once per chunkset.
  A local 500-chunk, three-build comparison measured 71.435 ms before and
  45.266 ms after, with identical budget text. This is a microbenchmark, not a
  capacity or latency commitment.
- Vector search counts authorized rows in the same SQL statement before LIMIT,
  avoiding a second membership/lifecycle join traversal and a separate snapshot.
- Synthetic protocol fixtures explicitly request a minimal dependency closure.
  A real local synthetic build measured 1,078 files / 0.90 s. Production retains
  the complete qualified closure. Fresh bubblewrap capabilities, native thread,
  Torch/Torchvision/Docling imports and real PDF/OCR extraction checks pass.
- QA cleanup tests inspect their own report directory, avoiding races with other
  simultaneous runs' temporary directories. Reproduced security regressions are
  included in required-case mappings; fixture version/rationale updates preserve
  the independent authored behavior expectations.

## Dependency remediation

All seven Composer lockfile audits returned zero known advisories and abandoned
packages. The initial Python OSV scan completed against 107 installed
distributions; the PyPI backend timed out. The [before-upgrade scan](2026-11-17-dependencies-before.json)
contains five advisory records representing four distinct CVEs for
`torch 2.9.1+cpu`:

| Finding | Reported severity | Reported fixed version |
| --- | --- | --- |
| [CVE-2026-24747](https://github.com/pytorch/pytorch/security/advisories/GHSA-63cw-57p8-fm3p) | High, 8.8 | 2.10.0 |
| [CVE-2025-3001](https://github.com/advisories/GHSA-qfhq-4f3w-5fph) | Low, 1.9 | 2.10.0 |
| [CVE-2025-3000](https://github.com/advisories/GHSA-rrmf-rvhw-rf47) | Low, 1.9 | 2.13.0 |
| [CVE-2026-4538](https://osv.dev/vulnerability/PYSEC-2026-139) | High, 7.8 | None listed by this scan |

The qualified dependency set now uses Torch **2.13.0+cpu**, Torchvision
**0.28.0+cpu**, and pypdfium2 **5.15.2**. The latter replaces yanked 5.15.1 and
fixes its shutdown cleanup regression while retaining the same native PDFium
binary. See the [upstream patch release](https://github.com/pypdfium2-team/pypdfium2/releases/tag/5.15.2).
The new versions installed through a verified wheelhouse and passed frozen
offline synchronization. The [final OSV scan](2026-11-17-dependencies.json) of all
107 installed distributions found no known vulnerabilities; this is an
advisory-database result, not a proof of
absence of every vulnerability. CVE-2026-4538 has no explicit fixed version in the
initial record; 2.13.0 is outside that record's affected range.

All 12 PDF/OCR reference IRs were independently compared before changing their
identities: text, spans, geometry, preview digests, coverage and OCR confidence
matched exactly after excluding only `parserSignature`. The updated profiles
were then checked inside a freshly built bubblewrap/seccomp runtime. E2E IR and
chunkset hashes came from real PHP extraction and persistence. Qualification
copies, notices, source URLs, fixture versions/rationales and dependent hashes
were updated together; no model weights were downloaded or replaced.
The [final equivalence record](2026-11-17-worker-equivalence.json) also compares
the final files directly against the pre-audit snapshot, binding both byte hashes
and old/new parser signatures.

This upgrade changes profile signatures and IR identity hashes. Jobs or callers
pinning previous signatures require explicit selection of the new qualification;
the update does not silently reinterpret their old identities. Closed model
inventory, hash checks, disabled TableFormer, network denial and private local-use
boundaries remain in effect.

Installed AgenTools delivery remains explicitly pending upstream; the registered
`bridge:runtime`, `bridge:migration`, `bridge-installed` and
`bridge-host-qualification` manifests/suites are unavailable. Existing source contracts cannot substitute
for those qualifications. Full release readiness must not be inferred from the
portable CI profiles or the line-coverage result.

The Torch 2.13.0 wheel's declared license expression combines Apache-2.0,
Apache-2.0 WITH LLVM-exception, BSD-2-Clause, BSD-3-Clause, BSL-1.0 and MIT.
All 98 declared license files are retained. They also include a GPLv3 text for
`third_party/kineto/libkineto/third_party/dynolog/third_party/cpr/test/LICENSE`;
the wheel RECORD lists its notice but not bundled cpr/test source. This is not
proof of linked GPL runtime code, nor a basis for asserting that distribution
has no additional obligations. Existing private local-use scope and
`redistributionAllowed: false` remain; distribution needs a separate review of
the included components and their obligations.
